Claude Code
Team Kit

● Opus 5│ ! ctx 82%│ myapp│ ▸ auth-refactor

A folder committed to the repo. It blocks Git write commands unless the developer asked for them in the same message, shows which model is active, warns at 80% and 90% context use, and writes a task summary file before /compact. Every developer on the repo gets the same behaviour.

Uses only existing Claude Code mechanisms: CLAUDE.md · hooks · skill · slash commands · settings.json

01 — The problem

Four problems it fixes

Each of these happened while using Claude Code on our projects.

Git

Claude commits and pushes without being asked

You ask it to fix a bug. It fixes the bug, then runs git add, git commit and git push. You never requested any Git action.

Lost work

Claude runs destructive Git commands

git reset --hard, git clean -fd, git checkout --. Uncommitted changes are deleted and cannot be recovered.

Context

/compact removes task information

Decisions, file changes and findings from the session are compressed away. The next session does not have them.

Consistency

Behaviour differs per developer

Each developer writes their own prompts, so the output depends on who is using it. There is no shared standard.

02 — What I built

What gets added to the repo

Cloning the repo is the whole setup. There is no per-developer install step.

repo/
  CLAUDE.md                        15 rules, read every turn
  .claude/settings.json            wiring: hooks, permissions, status line
  .claude/hooks/                   5 scripts that actually enforce things
  .claude/skills/context-handoff/  handoff format, loaded only when used
  .claude/commands/                /handoff /checkpoint /context /unknowns /resume-handoff
  .claude/scripts/                 data source for /context
  .claude/checkpoints/             working notes — gitignored
  docs/handoffs/                   finished-task records — committed
  docs/guide/                      8-chapter manual

Install is one command: ./install.sh /path/to/repo. If the repo already has a settings.json, the installer merges into it instead of replacing it.

03 — How rules are enforced

Rules are enforced at three different levels

Git commands and model detection are enforced by shell scripts. Style and reasoning rules are instructions only.

Layer 1Instructions — CLAUDE.md, the skill, the commands. The model reads them and usually follows them.
Layer 2Permissions — settings.json ask rules. Claude Code asks the developer before running the command.
Layer 3Hooks — shell scripts that return exit 2 and stop the command. The model cannot override this.

Git safety and model detection are at Layer 3. Rules like “do not assume” and “use simple English” are at Layer 1 only, because no script can check whether they were followed. The documentation states this.

04 — Git safety

Git write commands need a Git request in the same message

Permission applies to one message only. The rows below are output from running the hook, not examples.

Asking for one destructive operation does not permit a different one. Read-only Git commands — status, diff, log, show — are always allowed.

05 — How it works

How the Git guard decides

Two hooks. One saves the developer's message, the other checks it before any Bash command runs.

You type a message
      │
      ▼
UserPromptSubmit hook  →  saves your exact words to
                          $TMPDIR/claude-team-guard/<session>.prompt
      │
      ▼
Claude decides to run:  git commit -m "fix"
      │
      ▼
PreToolUse(Bash) hook  →  reads your saved message, matches intent
                          exit 0 = allow      exit 2 = block

Text returned to Claude when blocked

“Do NOT retry this command. Do NOT work around this hook. Ask the user to reply with the Git action.”

Turning the guard off

For a single command:
THINKTEAM_GIT_GUARD=off git rebase main

06 — Context handoff

A task summary file is written before /compact

One file per task, committed to the repo. It records decisions, changed files, risks, validation and the next step.

  1. 01ClaudeTask finishes. Prints CONTEXT HANDOFF AVAILABLE and asks. No file is written yet.
  2. 02YouSay yes.
  3. 03ClaudeWrites docs/handoffs/2026-08-26-refactor-auth.md — decisions, changed files, risks, validation, next step.
  4. 04ClaudePrints CONTEXT HANDOFF SAVED — YOU CAN NOW USE /compact and names what to preserve.
  5. 05YouRun /compact. Claude never runs it for you.

Each file ends with a Compact Focus section listing what to keep in detail and what to summarise, so the compaction is guided. /checkpoint writes the same kind of file for a task that is still in progress.

07 — Context budget

Context usage warnings at 80% and 90%

The percentage comes from the context_window.used_percentage value Claude Code sends to the status line. It is not estimated. If that value is unavailable, the system reports unknown.

under 60%ctx 42%nothing

80–89%! ctx 82%one warning
90%+!! ctx 91%one stronger warning
 
# fires ONCE per band, per session
# **CONTEXT WARNING — ~82% USED**
> Consider /checkpoint → /compact
> before continuing.

Each band fires once per session. The warning is not repeated on every reply.

08 — Model detection

Fable 5 is detected and shown on every reply

The hook reads the session transcript and takes message.model from the last assistant reply. Fable 5 can use more of the expensive allocation than the default model.

status line — always visible
⚠️  FABLE 5 — HIGH USAGE  │  ctx 34%  │  myapp

every reply while it is active
# **⚠️ FABLE 5 IS ACTIVE — USAGE MAY BE HIGHER**

first turn only — then it stops asking
> It may use more of the expensive team allocation.
> Do you want to continue with Fable 5?

Claude cannot change its own model. The rules forbid it from stating that it did. The developer changes the model with /model.

09 — Token discipline

Token cost of the rules

CLAUDE.md is re-read on every turn, so its length is a permanent cost. Only rules needed every turn are kept there.

CLAUDE.md

244 lines

Rules needed on every turn. Read on every turn.

Skill

209 lines

Handoff and checkpoint templates. Loaded only when one is being written.

Hooks

0 tokens idle

Each hook prints nothing unless a warning applies, so a normal turn adds no tokens.

CLAUDE.md also sets a search order for Claude: known file → known folder → grep → broad search. Work that requires reading many files is sent to a subagent; the subagent reads the files and returns only its result to the main session.

11 — Honest limits

What this does not enforce

These limits are listed in the documentation as well as here.

Cannot be enforcedWhat holds instead
Bypass permission mode skips permission rulesThe hook still runs, but a developer who wants to get around their own tooling can. It prevents accidental commands, not deliberate ones.
“No assumptions” cannot be checked by a scriptIt is a rule in CLAUDE.md. It is not enforced.
Git permission is matched by keyword“Don't push this yet” contains the word push, so it would grant permission for that turn. CLAUDE.md is the second check.
The Fable warning does not appear on turn 1There is no assistant reply yet to read the model from. The status line shows it correctly from the start.
Detecting that a new task startedA hook cannot tell a new task from a follow-up question, so this is left to the model.

Summary

What the kit does

Behaviour

Blocks unrequested Git write commands · blocks destructive Git unless named · writes task summary files before /compact · warns at 80% and 90% context · shows the active model · same rules for every developer on the repo.

Every behaviour shown here was produced by running the hooks. Line counts were measured. The installer was tested into a clean repo and into a repo with existing settings. An 8-chapter manual is in docs/guide/.
