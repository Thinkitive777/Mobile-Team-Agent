Internal tooling · reference sheet

Claude Code Team Kit

A folder committed to the repo. It blocks Git write commands unless the developer asked for them in the same message, shows which model is active, warns at 80% and 90% context use, and writes a task summary file before /compact. Every developer on the repo gets the same behaviour. Uses only existing Claude Code mechanisms: CLAUDE.md, hooks, a skill, slash commands, settings.json.

● Opus 5│ ! ctx 82%│ myapp│ ▸ auth-refactor│ status line: active model, context used, repo, open task

01 The problem

Each of these happened while using Claude Code on our projects.

Git

Claude commits and pushes without being asked

You ask it to fix a bug. It fixes the bug, then runs git add, git commit and git push. You never requested a Git action.

Lost work

Claude runs destructive Git commands

reset --hard, clean -fd, checkout --. Uncommitted changes are deleted and cannot be recovered.

Context

/compact removes task information

Decisions, file changes and findings are compressed away. The next session does not have them.

Consistency

Behaviour differs per developer

Each developer writes their own prompts, so the output depends on who is using it.

02 Rules are enforced at three levels

Git commands and model detection are enforced by shell scripts. Style and reasoning rules are instructions only.

Layer 1Instructions — CLAUDE.md, the skill, the commands. The model reads them and usually follows them.
Layer 2Permissions — settings.json ask rules. Claude Code asks the developer first.
Layer 3Hooks — shell scripts that return exit 2 and stop the command. The model cannot override this.

Git safety and model detection are at Layer 3. Rules like “do not assume” and “use simple English” are at Layer 1 only, because no script can check whether they were followed. The documentation states this.

03 Git safety

Git write commands need a Git request in the same message. Permission applies to one message only. The rows below are output from running the hook.

Asking for one destructive operation does not permit a different one. Read-only Git commands — status, diff, log, show — are always allowed. To skip the guard for a single command: THINKTEAM_GIT_GUARD=off.

04 How the guard decides

You type a message
      │
      ▼
UserPromptSubmit hook  →  saves your exact words to
                          $TMPDIR/claude-team-guard/<session>.prompt
      │
      ▼
Claude decides to run:  git commit -m "fix"
      │
      ▼
PreToolUse(Bash) hook  →  reads your saved message, matches intent
                          exit 0 = allow      exit 2 = block

The decision is made by the shell script from the developer's own message. The model is not consulted and cannot override the result.

05 Task summary file written before /compact

One file per task, committed to the repo. It records decisions, changed files, risks, validation and the next step.

  1. 01ClaudeTask finishes. Prints CONTEXT HANDOFF AVAILABLE and asks. No file is written yet.
  2. 02YouSay yes.
  3. 03ClaudeWrites docs/handoffs/2026-08-26-refactor-auth.md — decisions, changed files, risks, validation, next step.
  4. 04ClaudePrints CONTEXT HANDOFF SAVED — YOU CAN NOW USE /compact and names what to preserve.
  5. 05YouRun /compact. Claude never runs it for you.

Each file ends with a Compact Focus section listing what to keep in detail and what to summarise, so the compaction is guided. /checkpoint writes the same kind of file for a task still in progress.

Each band fires once per session; the warning is not repeated on every reply. Model detection reads message.model from the last assistant reply in the transcript. Claude cannot change its own model, and the rules forbid it from stating that it did.

07 Token cost of the rules

CLAUDE.md is re-read on every turn, so its length is a permanent cost. Only rules needed every turn are kept there.

CLAUDE.md also sets a search order: known file → known folder → grep → broad search. Work needing many files is sent to a subagent, which reads them and returns only its result to the main session.

09 What this does not enforce

These limits are listed in the documentation as well as here.

Cannot be enforcedWhat holds instead
Bypass permission mode skips permission rulesThe hook still runs, but a developer who wants to get around their own tooling can. It prevents accidental commands, not deliberate ones.
“No assumptions” cannot be checked by a scriptIt is a rule in CLAUDE.md. It is not enforced.
Git permission is matched by keyword“Don't push this yet” contains the word push, so it would grant permission for that turn. CLAUDE.md is the second check.
The Fable warning does not appear on turn 1There is no assistant reply yet to read the model from. The status line shows it correctly from the start.
Detecting that a new task startedA hook cannot tell a new task from a follow-up question, so this is left to the model.
